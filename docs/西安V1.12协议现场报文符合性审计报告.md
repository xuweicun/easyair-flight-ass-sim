### 3.2 关键发现

| 项目 | 值 | 影响 |
|---|---|---|
| `turnaround_id` | `FlightDataIsNone`（99%+） | 算法不绑定航班，IRS 需自行按机位+时间查航班 |
| 8/3 全天事件数 | 37,445 条 | 高频消费 |
| 事件类型 | OpenCabinDoor, CloseCabinDoor, LuggageCarBegin, OilseedsCarLeave, LadderCarStartLeave, AccessCorridorBridge, ReflectiveBucketPlacementStart 等 | 覆盖保障全流程 |
| `is_callback` | Y/N | Y=回调确认，N=首次上报 |
| 精简消息 | 部分 `ReflectiveBucketPlacementStart` 无 task_id/video | 需容错处理 |

### 3.3 事件名与算法 event 编码映射

IRS 出站 RocketMQ 使用数字 `event` 编码（如 `"event":"12"`），入站 Kafka 使用字符串
`event_name`（如 `"LuggageCarBegin"`）。映射关系由 IRS 内部维护：

| event_name (Kafka入站) | event 编码 (RocketMQ出站) | 含义 |
|---|---|---|
| LuggageCarBegin | 12 | 行李车就位 |
| OpenCabinDoor | 4 | 开客舱门 |
| LadderCarStartLeave | (待确认) | 客梯车撤离 |

## 5. 运行健康问题

### 5.1 MQTT 连接稳定性

| 指标 | 8/3 数值 | 严重性 |
|---|---|---|
| MQTT 重连次数 | **9,096 次/天** | ⚠️ 中等 |
| 平均间隔 | ~9.5 秒一次 | 网络或 Broker 抖动 |
| 关联 ERROR | 14,310 条/天 | 每次断连触发 RocketMQ asyncSend NPE |

### 5.2 RocketMQ asyncSend NPE

每次 MQTT 断连时，`RocketMQTemplate.asyncSend` 抛出 `NullPointerException`：
```
Caused by: java.lang.NullPointerException: null
    at org.apache.rocketmq.spring.core.RocketMQTemplate.asyncSend(RocketMQTemplate.java:732)
```
虽然 Netty 重试后最终成功发送，但空消息体 `message=[]` 被发送了两次（第一次有内容，
第二次为空），说明代码在 MQTT 回调中对空消息也执行了发送。

### 5.3 航班查询落空

大量 `getFlightInfoByStand4algo` 查询返回空结果，涉及机位 505/508/540/560/581/641/642/
645/907/910/912/913 等。可能原因：
- 夜间航班计划尚未同步
- 机位号与航班计划的绑定时间差
- 算法事件到达时航班数据尚未入库
