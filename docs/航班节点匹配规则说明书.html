01 · Executive Summary

执行摘要与规则状态

系统采用先聚类、后匹配的两阶段方法：先依据机位和飞机占位边界形成可独立保存的临时保障组，再用计划、顺序、节点语义、A-CDM 与外观证据关联正式航班。计划缺失或证据不足时，节点仍以临时组输出，任何处理都不得破坏节点总数守恒。

02 · Domain Model

业务对象与证据层级

系统把“飞机在机位上的一次连续保障”与“航班航段”拆成不同对象。前者依附航空器与机位，后者依附进港、过站和出港业务；二者通过可解释证据关联，而不是用保障编码硬拼。

对象定义关键标识状态
FlightPlan归一化后的驻位计划，可同时含进港和出港航班号flight_key、机位、时间窗、机号已实现
NodeEvent算法、人工现场或 A-CDM 上报的原子事件source_row_id、事件类型、时间、机位已实现
TemporaryFlightGroup同一机位上一次航空器连续占位对应的节点集合TMP-{机场}-{机位}-{日期}-{序号}已验证
Candidate临时组可能对应的正式驻位计划及逐项得分计划 ID、排名、得分、排除原因已实现
Review人工最终答案及策略运行时快照期望航班、期望状态、错误类型已验证

证据优先级

来源必须可追踪

  • 所有节点保留 source_type、原始内容、来源文件、行号、批次和导入时间。
  • 人工输入不得伪装为算法结果；A-CDM 仿真与未来真实接口走同一特征路径。
  • 原始批次和已发布策略不可修改；归一化升级新建批次并复制证据与人工结论。
03 · Plan Normalization

航班计划归一化与质量识别

航班计划不是绝对真值。系统先保留原始行，再将进港和出港记录归一成航空器驻位计划，并把可疑时间、机位和重复关系作为问题标签，而不是直接删除。

归一化规则

  1. 字段名支持中英文别名；实际起止时间优先于计划起止时间。
  2. 源记录先按“内部保障编码 + 机位”汇总，缺编码时使用源行号生成临时键。
  3. 进出港属性存在时分别填入进港、出港航班号；属性缺失时仅按出现顺序兜底，不能把内部编码解释为进出港。
  4. 同一飞机注册号、同一机位、完全相同时间窗下，若两组记录方向互补为 A 与 D，则合并为一个物理驻位计划。
  5. 保障编码保留作审计字段，不作为独立匹配证据。

问题计划识别

标签触发条件处理状态

04 · Node Clustering

节点聚类与保障组边界

聚类只回答“这些节点是否属于同一次航空器占位”，不提前假设航班号。所有有效节点先按机位、事件时间、节点 ID 稳定排序，再应用强边界和弱边界。

强边界和弱边界

边界事件行为
开始强边界飞机入位没有有效接近链时拆出新组；不能挂到前一航空器。
接近链飞机开始入位、引导车开始距飞机入位不超过 30 分钟时与入位留在同一新组。
结束强边界飞机推出、牵引车结束属于当前航班；之后出现的非结束节点开启下一组。
空闲弱边界相邻节点间隔超过 180 分钟即使没有飞机边界也拆组，进入人工复核。

边界次序规则

  • 飞机推出与牵引车结束无论谁先上报，都留在前一个保障组。
  • 下一航班的牵引车开始、飞机开始入位、飞机入位形成新组开始链。
  • 飞机入位前出现旧作业尾节点时，旧节点单独保留，不能跨过入位边界混入新组。
  • 结束边界不能因为更靠近下一航班计划开始时间而分给下一航班。

数据异常

类型判定结果
原始异常节点时间或机位缺失，或导入时标记异常进入 ERR-* 数据异常组
孤立开始标记单个飞机/引导开始节点，未形成入位链DATA_ERROR，标签 ORPHAN_START_MARKER
低信息碎片不超过 3 节点、时长不超过 120 秒、无飞机占位边界DATA_ERROR，保留原始节点审计
节点守恒
拆分、合并、数据异常和无航班号都只能改变归属状态，不能删除原始节点。每次运行必须满足“输入节点数 = 所有最终组节点数”。
05 · Dual Attribution

航空器与航班双维归属

一次保障组可以跨越两个航班：飞机入位到下客属于进港航班，过站准备和离港阶段属于后续出港航班。同一航班也可能因西安换飞机、换机位而由两个保障组共同构成。

节点阶段

阶段典型节点默认航班归属
ARRIVAL开始入位、引导、飞机入位、放轮挡、靠桥、开门、首件行李进港航班 A
TURNAROUND加油、配餐、行李装卸等双向保障作业当前实现默认出港航班 B；具体业务可在生产代码复核
DEPARTURE关门、撤桥、撤轮挡、牵引、推出、开始滑行出港航班 B
货舱门规则
开货舱门属于进港卸载准备，关货舱门属于出港装载完成。重复开关门或行李装卸节点必须保留时间顺序，不应仅按节点名称“一刀切”。

两种查看方式

视角组织方式回答的问题
航空器 / 保障组同一架飞机的一组连续节点，标出前半段航班 A、后半段航班 B这架飞机在机位上经历了什么？
航班聚合同航班号在不同机位、不同飞机上的关联片段该航班在中转换飞机后由哪些保障组共同完成？

占位时间

  • 开始优先级：A-CDM 飞机入位 ＞ 算法飞机入位 ＞ 保障组首节点。
  • 结束优先级：算法飞机推出/牵引车结束 ＞ A-CDM 人工释放机位 ＞ 保障组末节点。
  • 实际结束晚于计划结束超过 20 分钟时标记 PLAN_END_OVERRUN，并进入问题库。
业务规则待接入生产代码复核 同航班号跨机位换飞机的完整链路必须结合飞机注册号和人工答案验证，不能只凭航班号合并航空器保障组。
06 · Matching

候选生成、评分与顺序消歧

时间不是五分钟内才可信的硬门槛，而是连续衰减证据。系统同时看机位、时间、节点阶段、链路连续性、同机位计划顺序和参考特征，并公开每项得分。

候选生成

  • 默认只取同机位计划，候选计划与保障组相距不超过 8 小时。
  • 计划时间缺失不能进入正常评分；计划时长小于 0 或超过 24 小时硬拒绝。
  • A-CDM 航班号找不到同机位计划时，允许查找跨机位同航班计划；若同机位已存在匹配，则排除跨机位同号计划。

评分项与基线权重

评分项权重计算原则
机位一致 stand30完全一致加分；普通路径不同机位为 0。
可信时间窗 time_window25开始、结束分别按 180 分钟连续衰减后取平均，无五分钟硬判断。
节点阶段 node_semantics20依据开始/结束节点占比选择与计划开始、结束或中心的距离。
链路连续 continuity15节点落入计划窗的覆盖率。
A-CDM 航班号不计分作为独立辅助项显示一致、冲突、无计划或多计划结论，不改变候选总分与领先分差。
同机位顺序 sequence_order40仅当前一组已有可靠锚点、计划序号对应且时间窗真实重叠时加分。
航司外观 appearance_airline±8置信度达到 0.75 后，同航司加分、矛盾扣分。
机型外观 appearance_type±5与航司规则相同，不单独强绑。
注册号 OCR appearance_registration最高 12相似度超过 0.5 后按 OCR 置信度连续加分。

自动匹配门槛

最高候选得分至少 70、领先第二候选至少 15，且不存在参考冲突、实际结束超计划、A-CDM 时间异常或 A-CDM 多计划歧义，才进入 MATCHED。否则保留候选并进入 NEEDS_REVIEW。

顺序证据边界
同机位计划顺序与实际保障顺序高度可靠，但两者必须有时间重叠。只有排序相邻、时间完全不相交时，顺序证据不能把它们强行绑定。
07 · Reference Evidence

A-CDM 与外观证据

人工现场 A-CDM 航班号是独立辅助证据，不进入候选评分。它可用于唯一确认、计划缺失补齐和冲突复核，但不改变算法基础分与领先分差。人工时间允许数分钟偏差；飞机入位是绝对占位开始，上轮挡等中间节点轻微错序只标记异常。

A-CDM 决策

情况系统行为状态
航班号唯一命中同机位计划选中该计划，置信度 100%MATCHED_REFERENCE
计划中没有该航班号保留 A-CDM 航班号，不伪造计划 IDMATCHED_REFERENCE_NO_PLAN
同号命中多计划标记 ACDM_FLIGHT_AMBIGUOUS，进入人工复核NEEDS_REVIEW
时间超出保障组 ±10 分钟标记 ACDM_TIME_OUTLIER；可靠航班号仍可确认保留解释
上轮挡早于入位标记 ACDM_NODE_ORDER_ANOMALY；占位开始仍取入位非阻断

外观与注册号

  • 人工模拟和未来真实算法都调用同一特征接口，不允许另建一套评分路径。
  • 航司、机型在置信度低于 0.75 时不参与强消歧。
  • 注册号先去除连字符和非字母数字字符，再用 OCR 感知的 Damerau-Levenshtein 相似度。
  • 易混字符组：0/O/Q、1/I/L、2/Z、5/S、6/G、8/B；易混替换成本 0.35，相邻交换成本 0.5。
  • B533 与 B53B 的相似度必须高于与 B524 的相似度。
业务规则待接入生产代码复核 未来 OCR 输出需要同时提供原图时间、摄像机、候选字符串和置信度，便于判断识别误差而非匹配逻辑错误。
08 · Human Loop

人工核验、回归与发布门禁

闭环不是人工直接覆盖系统结果，而是保存“策略原结论、A-CDM 锚点、最终人工答案”三份数据。任何指出的错误都必须进入后续全量回归。

人工动作

动作结果审计要求
匹配正确保存当前明确匹配为期望答案策略尚无明确航班时禁止提交
纠正航班MATCHED_MANUAL 或无计划参考航班保存原策略航班与最终航班
保留无航班号UNASSIGNED候选仅进审计附件，不对外发送
标记数据异常DATA_ERROR原始节点仍保留并计入守恒
拆分 / 合并原组 SUPERSEDED，新组保留血缘节点集合必须精确守恒

错误分类

分组错误、航班匹配错误、参考数据错误、外观特征错误、原始节点异常。建议只能生成策略草稿，不允许自动发布。

闭环状态机

两套验收门禁

  • A-CDM 闭环：已选歧义样本全部审核，策略错误、A-CDM 冲突、闭环回退均为 0。
  • 全量发布：全部必审问题核验、人工指出问题为 0、历史正确案例无回退、节点数量守恒。运行 #27 仍有全量问题池未审核，因此策略保持草稿。

10 · Contracts

输出、接口与不变量

输出合同必须让下游知道“系统确认了什么”和“系统仍不知道什么”。内部候选评分不能伪装成正式航班信息。

无航班号输出

  • flight_no、safeguard_code 保持空值，状态为 UNASSIGNED。
  • 提供临时组编号、机场、机位、观测起止、节点列表、来源、聚类置信度和外观推测。
  • 候选航班及评分只进入审计附件；首版仅 JSON/Excel 预览导出，不连接生产接收方。

公开接口分组

能力接口
批次与运行/api/batches、/api/batches/import、/api/runs、/api/dashboard
保障组/api/groups、/api/groups/{id}、/split、/merge
证据/api/references/acdm/import、/simulate、/api/features/appearance、/registration-similarity
闭环/reviews、/acdm-validation、/suggestions、/acceptance、/publish
双维与导出/associations/groups、/associations/flights、/exports/unassigned.*

系统不变量

  1. 每个节点最终只属于一个有效组、无航班号组或数据异常组。
  2. 同一批次和策略版本重复运行结果一致。
  3. 原始记录、策略版本、人工答案不可静默覆盖。
  4. 每个匹配结果含候选、逐项得分、排除原因、领先分差和策略版本。
  5. 轮询只在后台任务运行时存在，页面隐藏或任务结束后停止。
