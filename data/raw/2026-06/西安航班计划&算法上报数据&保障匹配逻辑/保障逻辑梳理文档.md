# 航班保障逻辑梳理文档

## 一、概述

本文档梳理航班保障系统的核心业务逻辑，重点说明保障节点处理流程、航班匹配逻辑以及保障节点状态维护机制。

---

## 二、保障节点处理流程

### 2.1 整体流程图

```
Kafka消息监听
    ↓
消息解析与校验
    ↓
航班匹配（获取保障编码）
    ↓
节点重复性校验
    ↓
节点数据处理
    ↓
保障监控信息更新
    ↓
告警规则检查
    ↓
消息确认
```

### 2.2 核心类说明

| 类名 | 职责 |
|------|------|
| `TurnaroundMqService` | Kafka消息监听入口，负责接收保障事件消息 |
| `TurnaroundMsgHandle` | 保障节点消息处理核心类，负责航班匹配、节点数据处理 |
| `AlarmDataHandler` | 告警数据处理类，负责节点告警规则检查 |
| `SafeguardMonitorInfoService` | 保障监控信息服务，负责保障状态维护 |
| `SafeguardNodeInfoService` | 保障节点信息服务，负责节点数据持久化 |

## 三、航班匹配逻辑（重点）

### 3.1 匹配流程

航班匹配逻辑位于 `TurnaroundMsgHandle.handlerFlightSafeguardCode()` 方法，主要分为三个阶段：

#### 阶段一：保障记录查询（快速匹配）

```java
// 1. 查询条件
- 机位 = eventInfo.getStandName()
- 保障状态 = "0"（保障中）
- 开始保障时间 在昨天00:00:00 到今天23:59:59之间
- 按创建时间倒序，取第一条
```

**匹配规则：**
- 如果事件类型为航班数据（`turnaround_flight`）或非引导车开始/飞机入位节点，优先查询保障监控表
- 找到保障记录后，进行时间校验：
  - 节点事件时间必须 >= 航班实际开始占用时间（或计划开始占用时间）
  - 否则返回空字符串（不匹配）

#### 阶段二：航班计划表匹配（精确匹配）

```java
// 2. 查询条件
- 机位 = eventInfo.getStandName()
- 从航班计划表获取航班列表
```

**匹配步骤：**

1. **按保障编码分组**：将航班列表按 `safeguardCode` 分组
2. **计算航班占用时间窗口**：
   - 开始时间 = min(进港实际开始, 进港计划开始, 出港实际开始, 出港计划开始)
   - 结束时间 = max(进港实际结束, 进港计划结束, 出港实际结束, 出港计划结束)
3. **时间窗口匹配**：
   - 事件时间在 [开始时间-5分钟, 结束时间+5分钟] 范围内
4. **选择最接近航班**：
   - 从匹配的航班中，选择事件时间与航班开始时间差值最小的航班

#### 阶段三：返回保障编码

```java
// 返回匹配到的保障编码
return safeguardCode;
```

### 3.2 航班时间计算逻辑

**进港航班（A）：**
- 开始时间：优先取 `realStart`，其次取 `planStart`
- 结束时间：优先取 `realEnd`，其次取 `planEnd`

**出港航班（D）：**
- 开始时间：优先取 `realStart`，其次取 `planStart`
- 结束时间：优先取 `realEnd`，其次取 `planEnd`

**组合规则：**
- 最终开始时间 = min(进港开始时间, 出港开始时间)
- 最终结束时间 = max(进港结束时间, 出港结束时间)

### 3.3 匹配流程图

```
开始
  ↓
是否为航班数据或非开始节点？
  ├─ 是 → 查询保障监控表（保障中状态）
  │         ↓
  │      找到记录？
  │         ├─ 是 → 时间校验
  │         │         ↓
  │         │      通过？
  │         │         ├─ 是 → 返回保障编码
  │         │         └─ 否 → 继续航班计划匹配
  │         └─ 否 → 继续航班计划匹配
  │
  └─ 否 → 查询航班计划表
            ↓
         按保障编码分组
            ↓
         计算时间窗口
            ↓
         时间窗口匹配
            ↓
         选择最接近航班
            ↓
         返回保障编码
```

## 四、保障节点状态维护逻辑（重点）

### 4.1 保障状态定义

| 状态值 | 含义 | 说明 |
|--------|------|------|
| 0 | 保障中 | 航班正在进行保障作业 |
| 1 | 已保障 | 航班保障作业已完成 |
| 2 | 保障异常 | 保障过程中出现异常 |

### 4.2 状态维护时机

#### 4.2.1 节点重复性校验（checkNodeHandle）

**校验逻辑：**

1. **查询节点是否存在**
   - 查询保障节点表中是否已存在相同节点（排除飞机推出节点）

2. **保障状态判断**
   ```java
   if (保障状态 == "0" && 保障中) {
       // 查询飞机推出节点时间
       if (飞机推出节点时间 < 当前节点时间) {
           // 不处理，直接返回
           return true;
       }
   } else if (保障状态 == "1" || 保障状态 == "2") {
       // 已保障或保障异常，不处理
       return true;
   }
   ```

**核心逻辑：**
- 如果航班已保障或保障异常，不再处理新节点
- 如果航班保障中，但飞机已推出，且推出时间早于当前节点时间，则不处理

#### 4.2.2 节点数据处理（handleNodeData）

**特殊节点处理：**

| 节点类型 | 处理逻辑 |
|----------|----------|
| 飞机入位（AircraftEntry） | 自动生成上轮挡节点（+动态时间偏移） |
| 牵引车就位（TowArrival） | 自动生成撤轮挡节点（-动态时间偏移） |
| 完成靠接（AccessCorridorBridge） | 根据规则配置动态调整节点时间 |
| 撤廊桥结束（RemoveCorridorBridge） | 根据规则配置动态调整节点时间 |

**时间偏移计算：**
```java
// 从动态节点配置表获取时间偏移
timeOffset = dynamicNode.getTimeOffset() + random(0-10秒)
```

### 4.3 保障监控信息创建与更新

#### 4.3.1 创建时机

当首次识别到航班保障节点时，创建保障监控记录：
- 保障状态初始化为 "0"（保障中）
- 记录开始保障时间
- 关联保障编码、机位、航班号等信息

#### 4.3.2 更新时机

**状态更新为"已保障"（1）：**
- 飞机推出节点识别完成
- 所有保障节点处理完成

**状态更新为"保障异常"（2）：**
- 特定异常场景（如NT/STLS消息触发）

### 4.4 节点状态流转图

```
保障开始
  ↓
创建保障监控记录（状态=0）
  ↓
接收保障节点数据
  ↓
节点重复性校验
  ├─ 已存在且保障中 → 检查飞机推出时间
  │                     ↓
  │                  推出时间 < 当前节点时间？
  │                     ├─ 是 → 不处理
  │                     └─ 否 → 继续处理
  │
  ├─ 已存在且已保障 → 不处理
  │
  └─ 不存在或可处理 → 保存节点数据
                        ↓
                     告警规则检查
                        ↓
                     更新保障状态（如需要）
```

## 六、告警规则检查

### 6.1 告警类型

| 类型 | 说明 |
|------|------|
| 延误告警（1） | 节点执行时间超过规定时间 |
| 偏差告警（2） | 节点执行顺序或时间不符合标准 |
| 缺失告警（3） | 必要节点未执行 |
| 超时告警（4） | 节点在规定时间内未完成 |

### 6.2 告警检查流程

```
查询机位规则配置
    ↓
获取告警规则列表
    ↓
遍历每条规则
    ↓
规则条件验证
    ├─ 延误告警 → 检查节点执行时间
    ├─ 偏差告警 → 检查节点时间偏差
    ├─ 缺失告警 → 检查节点是否存在
    └─ 超时告警 → 检查节点执行时长
    ↓
生成告警记录
```

## 九、总结

### 9.1 核心流程总结

1. **航班匹配**：优先从保障监控表快速匹配，失败后从航班计划表精确匹配
2. **状态维护**：通过保障监控表维护保障状态，防止重复处理
3. **节点处理**：支持动态时间偏移和规则配置，灵活处理各类节点
4. **告警检查**：支持多种告警类型，实时监控保障过程

### 9.2 关键设计点

- **时间窗口匹配**：使用±5分钟的时间窗口，提高匹配成功率
- **状态防重**：通过保障状态和节点重复性校验，避免重复处理
- **动态时间偏移**：支持节点时间的动态调整，适应实际作业场景
- **规则引擎**：支持灵活的告警规则配置，满足不同场景需求
